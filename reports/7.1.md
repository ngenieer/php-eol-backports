# PHP 7.1 backport verification report (2026-10-25)

- Base: php-7.1.33 (last release of the 7.1 branch)
- Source: this repository's 7.2 backport (← 7.3 backport ← php-src official 7.4 EOL backport 712e60f9ed)
- Patch: `patches/7.1/0001-CVE-2026-109618-109619-avoid-state-corruption-via-bailout.patch`

## Porting

| File | Handling |
|---|---|
| Zend/zend_execute_API.c | 7.1's `shutdown_executor` has no fast-shutdown path and always does a full cleanup. The intent of the patch (return global state that may be used before the next request to safe values) was ported as follows: reset `EG(error_handling)` and `EG(exception)` right after the object store cleanup, and at the very end of the function unconditionally reset the error/exception handlers, the handler stacks and objects_store. Even if an intermediate cleanup step is skipped by a bailout, the final reset always runs. |
| Zend/zend_alloc.c | 7.1's `zend_mm_alloc_huge` has no size alignment overflow check at all, so one was added (exits immediately via `zend_mm_safe_error_ex`) |
| Zend/zend_vm_def.h | 7.1's FAST_CONCAT has no string fast path, so the length overflow check was added to the existing allocation path. CONCAT applied as is |
| main/php_variables.c | Replaced the 4 GPC array creations with `array_init_singleton` |
| Zend/zend_vm_execute.h | See below |

### Handling of the generated executor file
Running 7.1's `zend_vm_gen.php` under PHP 8.3 produces a file that differs from the shipped one by about 1,300 lines, unrelated to the patch (unused variable declarations and the like). The unpatched and patched `zend_vm_def.h` were therefore each generated with the same generator, and **only the difference between the two outputs (81 lines) was applied to the shipped `zend_vm_execute.h`**.

## Test comparison
Build: `--disable-all --enable-session --enable-cli --enable-cgi`, gcc 13.3

| | 7.1.33 unpatched | 7.1 backport |
|---|---|---|
| Passed | 4,770 | 4,762 |
| Failed | 33 | 41 |

The tests failing only after the patch are the same 9 as for the official 7.4 backport. On the first run `tests/basic/timeout_variation_4.phpt` also failed; this was timing jitter caused by running the unpatched and patched suites at the same time on a shared CPU. Run alone 5 times on the patched build, it passed every time (the unpatched build also passed 5 times). `compare-tests.sh` now runs the two suites one after the other.

## Limitations
Same as the 7.3 report: the vulnerabilities were not reproduced, verification used a minimal build, and the patch is not endorsed by php.net. In particular, the shutdown changes for 7.1 and 7.0 are not a port of official code but were written anew with the same intent.
