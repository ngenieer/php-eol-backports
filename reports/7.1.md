# PHP 7.1 백포트 검증 보고 (2026-10-25)

- 기준: php-7.1.33 (7.1 브랜치 최종 릴리스)
- 원본: 이 레포의 7.2 백포트 (← 7.3 백포트 ← php-src 7.4 공식 EOL 백포트 712e60f9ed)
- 패치: `patches/7.1/0001-CVE-2026-109618-109619-avoid-state-corruption-via-bailout.patch`

## 포팅 내용

| 파일 | 처리 |
|---|---|
| Zend/zend_execute_API.c | 7.1의 `shutdown_executor`는 빠른 종료 경로 없이 매번 전체 정리를 합니다. 패치의 의도(다음 요청 전에 쓰일 수 있는 전역 상태를 안전한 값으로 되돌림)를 이렇게 옮겼습니다: 객체 저장소 정리 직후 `EG(error_handling)`·`EG(exception)` 리셋, 함수 맨 끝에서 오류·예외 핸들러와 핸들러 스택, objects_store를 무조건 리셋. 중간 정리 단계가 bailout으로 건너뛰어져도 마지막 리셋은 반드시 실행됩니다. |
| Zend/zend_alloc.c | 7.1의 `zend_mm_alloc_huge`에는 크기 정렬 오버플로 검사가 아예 없어서 새로 추가 (`zend_mm_safe_error_ex`로 즉시 종료) |
| Zend/zend_vm_def.h | 7.1의 FAST_CONCAT에는 문자열 빠른 경로가 없어, 기존 할당 경로에 길이 오버플로 검사 추가. CONCAT은 그대로 적용 |
| main/php_variables.c | GPC 배열 생성 4곳을 `array_init_singleton`으로 교체 |
| Zend/zend_vm_execute.h | 아래 참고 |

### 실행기 생성 파일 처리
PHP 8.3으로 7.1의 `zend_vm_gen.php`를 돌리면, 패치와 무관하게 출시본과 1,300줄가량 다른 파일이 나옵니다(쓰이지 않는 변수 선언 등). 그래서 원본과 패치본의 `zend_vm_def.h`를 같은 생성기로 각각 생성한 뒤 **두 결과의 차이(81줄)만 출시본 `zend_vm_execute.h`에 적용**했습니다.
