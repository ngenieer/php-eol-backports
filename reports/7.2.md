# PHP 7.2 backport verification report (2026-10-25)

- Base: php-7.2.34 (last release of the 7.2 branch)
- Source: this repository's 7.3 backport (← php-src official 7.4 EOL backport 712e60f9ed)
- Patch: `patches/7.2/0001-CVE-2026-109618-109619-avoid-state-corruption-via-bailout.patch`

## Porting
Cherry-picking the 7.3 backport produced conflicts in 7 files, resolved by hand. Shutdown (zend_execute_API.c), the memory allocator (zend_alloc.c), upload handling (rfc1867.c), SAPI.c and main.c applied cleanly.

| File | Handling |
|---|---|
| Zend/zend_hash.c / .h | 7.2 has no `_zend_new_array_0`, so `zend_new_array_singleton()` was written against the 7.2 API (`_zend_hash_init`, then `nTableSize = 1`) |
| Zend/zend_API.h | Kept 7.2's existing `array_init` definitions and added only the `array_init_singleton` macro |
| Zend/zend_types.h | No change. The upstream change handles hashes smaller than 64 bytes in the 7.3+ SSE2 `HT_HASH_RESET`; 7.2 uses only memset, so a single-slot hash is already safe |
| Zend/zend_vm_def.h | Inserted the CONCAT/FAST_CONCAT length overflow checks inside 7.2's do-while structure |
| Zend/zend_vm_execute.h | Regenerated with 7.2's `zend_vm_gen.php` |
| main/php_variables.c | Kept the 7.2 code and replaced the 4 GPC array creations with `array_init_singleton` |
| ext/session/session.c | `true` is not declared in 7.2, so `|| true` is written as `|| 1` (same meaning: upload progress disabled) |

## Test comparison
Build: `--disable-all --enable-session --enable-cli --enable-cgi`, gcc 13.3

| | 7.2.34 unpatched | 7.2 backport |
|---|---|---|
| Passed | 4,872 | 4,863 |
| Failed | 43 | 52 |
| Failing only after the patch | | 9 |

**The 9 tests that fail only after the patch are exactly the same as for the official 7.4 backport** (see EXPECTED-CHANGES.md). The 43 tests that already fail unpatched are caused by the current build environment and are unrelated to the patch.

## Revision history
- 2026-10-25: After cross-checking against Sury's package patches, the reset of the user error/exception handlers on fast shutdown was moved **before** `zend_objects_store_free_object_storage()` (the same order as the official 7.4 fix and Sury). In the earlier position there was a window in which a closure handler was still referenced after being freed. Docker verification results after the change are unchanged. Details in [sury-crosscheck.md](sury-crosscheck.md).

## Limitations
Same as the 7.3 report: the vulnerabilities were not reproduced, verification used a minimal build, and the patch is not endorsed by php.net.
