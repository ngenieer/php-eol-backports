# PHP 7.3 backport verification report (2026-10-25)

- Base: php-7.3.33 (last release of the 7.3 branch)
- Source: commit 712e60f9ed ("Avoid state corruption via bailout") on the php-src branch `PHP-7.4-CVE-2026-109618-109619`
- Patch: `patches/7.3/0001-CVE-2026-109618-109619-avoid-state-corruption-via-bailout.patch`

## Porting
Cherry-picking the 7.4 patch produced 4 conflicts, resolved by hand. The other 13 files applied cleanly.

| File | Handling |
|---|---|
| Zend/zend_alloc.c | Added `#include "zend_execute.h"` (7.3 already includes signal.h conditionally) |
| Zend/zend_alloc.h | Added only the `zend_mm_safe_error_ex` declaration (the 7.4-only ZTS declaration is left out) |
| Zend/zend_string.h | Added the `ZSTR_MAX_OVERHEAD` and `ZSTR_MAX_LEN` macros, which 7.3 lacks, exactly as defined in 7.4 |
| Zend/zend_vm_def.h | Added the length overflow checks to CONCAT/FAST_CONCAT |
| Zend/zend_execute_API.c | Ported with the same meaning onto 7.3's shutdown_executor: on fast shutdown, reset the user error/exception handlers before freeing the object store, reset objects_store, reset `EG(error_handling)` and `EG(exception)` |
| Zend/zend_vm_execute.h | Not edited by hand; regenerated with 7.3's `zend_vm_gen.php` |

## Test comparison
Build: `--disable-all --enable-session --enable-cli --enable-cgi`, gcc 13.3
Suites: Zend/tests, tests, main, ext/session, ext/standard/tests/file, ext/standard/tests/strings (5,554 tests)

| | 7.3.33 unpatched | 7.3 backport | 7.4.33 unpatched | 7.4 official backport |
|---|---|---|---|---|
| Passed | 4,986 | 4,977 | 5,112 | 5,103 |
| Failed | 54 | 63 | 6 | 15 |
| Failing only after the patch | | 9 | | 9 |

**The 9 tests that fail only after the 7.3 backport are exactly the same as for the official 7.4 backport.** All of them are the intended behaviour changes in EXPECTED-CHANGES.md. The 54 tests that already fail unpatched are pre-existing failures caused by a current gcc and environment, unrelated to the patch.

## Revision history
- 2026-10-25: After cross-checking against Sury's package patches, the reset of the user error/exception handlers on fast shutdown was moved **before** `zend_objects_store_free_object_storage()` (the same order as the official 7.4 fix and Sury). In the earlier position there was a window in which a closure handler was still referenced after being freed. Docker verification results after the change are unchanged. Details in [sury-crosscheck.md](sury-crosscheck.md).

## Limitations
- The vulnerabilities were not reproduced to confirm they are blocked. What was verified is that the same code changes as the official patch produce the same behaviour changes.
- Verified with a minimal build. Rebuild with a server's actual extension set (mysqli, gd, opcache, etc.) and run the same comparison (see [docker.md](docker.md)).
- Not reviewed or endorsed by php.net.
