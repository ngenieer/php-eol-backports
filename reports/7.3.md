# PHP 7.3 백포트 검증 보고 (2026-10-25)

- 기준: php-7.3.33 (7.3 브랜치 최종 릴리스)
- 원본: php-src `PHP-7.4-CVE-2026-109618-109619` 브랜치의 712e60f9ed ("Avoid state corruption via bailout")
- 패치: `patches/7.3/0001-CVE-2026-109618-109619-avoid-state-corruption-via-bailout.patch`

## 포팅 내용
7.4 패치를 cherry-pick 했을 때 충돌 4곳을 수동으로 해결했습니다. 나머지 13개 파일은 그대로 적용됐습니다.

| 파일 | 처리 |
|---|---|
| Zend/zend_alloc.c | `#include "zend_execute.h"` 추가 (7.3은 signal.h를 조건부로 이미 포함) |
| Zend/zend_alloc.h | `zend_mm_safe_error_ex` 선언만 추가 (7.4 전용 ZTS 선언 제외) |
| Zend/zend_string.h | 7.3에 없는 `ZSTR_MAX_OVERHEAD`, `ZSTR_MAX_LEN` 매크로를 7.4 정의 그대로 추가 |
| Zend/zend_vm_def.h | CONCAT/FAST_CONCAT 길이 오버플로 검사 추가 |
| Zend/zend_execute_API.c | 7.3의 shutdown_executor 구조에 맞게 같은 의미로 이식: 빠른 종료 경로에서 오류·예외 핸들러 초기화, objects_store 리셋, `EG(error_handling)`·`EG(exception)` 리셋 |
| Zend/zend_vm_execute.h | 손으로 고치지 않고 7.3의 `zend_vm_gen.php`로 재생성 |

## 한계
- 취약점을 실제로 재현해 막히는지는 확인하지 않았습니다. 공식 패치와 같은 코드 변경이 같은 동작 변화를 일으킨다는 것까지 확인한 것입니다.
- 최소 구성 빌드로 검증했습니다. 고객 서버의 확장 모듈 조합(mysqli, gd, opcache 등)으로 다시 빌드해 같은 비교를 돌려야 합니다.
- php.net이 검토하거나 보증한 패치가 아닙니다.
